## 2. 기능 및 UX 상세

1. **동축 비교:** 69명 대표 평가 로스터에서 선택 가능, 동일 캐릭터 대진 제한, 최근 점수에 가까운 다른 캐릭터를 첫 상대로 제시. 2열 구성은 작은 화면에서 1열 세로 비교로 변경.
2. **점수:** Balanced1.2의 `hakiWeight`를 Repository에서 실제 읽고, 개별 캐릭터의 `Base/Raw/Effective/Final`과 E1/E2/E3, 평가 상태·평가 시점을 표시. 상한 100점 적용 여부 표시. 새로운 종합 계산, 고정 상성 보너스·승률·승자 판정 없음.
3. **Evidence:** 실제 연결 `evidenceIds`를 해당 캐릭터 소유 자료에서 찾아 Fact, Battle 제한/외부 요인, Interpretation, source type·role, 링크로 보여 줌. 연결 오류가 있으면 숫자를 임의 보정하지 않고 누락 건수를 표시함. 3개 초과는 펼치기 버튼 사용.
4. **Attack 감사:** 기존 6인(킹/카타쿠리/퀸/마르코/크래커/스무디) 4요소 `peakOutput/verifiedHit/sustainedPressure/matchup`를 Attack 선택 시 별도 질적 근거로 보여 줌. 임의의 서브스탯 없음.
5. **근거 탐색:** 기존 평가 근거에 나열된 각 출처를 클릭하면 해당 `battleId`의 기존 타임라인 상세로 이동. 전투 기록을 새로 복제하지 않음.
6. **접근성·성능:** Escape, 키보드 Tab 포커스 순환, 닫은 뒤 포커스 복귀, 모달 열기 동안 바디 스크롤 잠금, 이미지 lazy/decoding 및 오류 대체 처리. 기존 Matchup Arena, 그룹 선택기, 랭킹은 건드리지 않음.

## 3. 초상 이미지 정책

현재 라이선스 검증이 완료된 ONE PIECE 캐릭터 이미지 파일이 제공되지 않았으므로 초상 이미지 **0개**를 등록했다. 이 결과는 의도적인 안전 조치다. 앱의 크기별 초상 영역에는 그룹 컬러 및 이름의 첫 글자 기반 대체 그래픽이 표시된다.

허가된 미디어를 추가할 때 `public/images/characters/<id>.webp` 등의 자체 자산과 manifest의 **fileName, alt, sourceUrl, permission, permissionNote**를 동시에 검토한다. 외부 공식 페이지 링크는 캐릭터의 근거로 사용할 수 있지만, 해당 사이트 이미지의 자동 사용 허가를 의미하지 않는다. 무단 다운로드/재배포/핫링크를 하지 않는다. 저작권 허락이 불명확하면 계속 대체 그래픽을 사용한다.

## 4. 점수 변경 없이 제안하는 **후속 검토 후보**

다음 표는 **현행 저장소 평가 데이터의 점수/Readiness/평가 이유**를 읽어 선별한 감사 후보이지, 외부 원작을 이번에 새로 검증했다는 주장은 아니다. 어떠한 자동 감점이나 재평가는 제안하지 않는다.

| 유형 | 평가 사례 (현재 저장값) | 왜 재검토하나 | 잠정 제안 |
|---|---|---|---|
| 최상단 E3 | 전성기 가프 Stamina99 / Speed98 / Combat IQ97 (E3) | God Valley 공동전·노년 하치노스의 개인 성과를 시대/전투 조건을 분리하며 재현할 필요 | **원작 교차 확인, 수치 유지** |
| 상급 E3 | 미호크 Stamina91 / Speed94 / Combat IQ92 (E3) | 장기 고강도 결투와 상위권 상대 반복 반응·판단의 직접 표본 제한 | **추가 근거 확인, 수치 유지** |
| 고위권 E3 | 샹크스 Stamina88 / Speed95 (E3) | 지속적인 장기 결투와 실전 이동 속도를 미래예지 정보와 분리 | **근거 분리 재검토, 수치 유지** |
| 상대 측정 부족 | 로 Speed82 (E3) | ROOM 순간이동과 순수 신체 기동을 섞지 않기 | **판정 근거 유지·확대** |
| 상호작용 부족 | 스무디 Speed74 (E3, 직접 링크 0개) | 써니호의 조타 회피와 스무디 신체 속도는 별개 | **근거 부족 안내 우선** |
| 수단과 기동 혼동 | 퀸 Speed75 (E3) | 레이저·무장 선택폭은 개인 속도 점수와 다른 의미 | **동축 Speed 비교 대상으로 검토** |

향후에는 (a) 높은 E3가 관찰 부족일 뿐 능력 부족이라는 뜻이 아닌지, (b) 하나의 Haki Raw Evidence가 여러 축에 연계돼도 독립적 효과가 입증되는지, (c) 실전 피격·임무·지형·공동전 조건의 누락이 없는지를 우선 분석한다. 기존 `V0_1_58_...` 문서의 13개 Raw 중복 검토 후보는 그 당시 코호트 기록이므로 현행 69명에 기계적으로 동일 건수라고 말하지 않는다. 숫자 조정과 모델 변경은 별도 승인 후에만.

- 확대 테스트: `getStatComparison.test.ts` (동일축 수치 보존, 6인 Attack 감사, 69명·평가 시점·Evidence 소유 및 Battle 연결), 초상 registry/fallback 단위·DOM 검증, `App.test.tsx`의 비교·검색·근거 타임라인·과거 패치 내역 회귀.
- 구현 diff에 기존 `src/data/sample/evaluations.ts`, `characters.ts`, `battles.ts`, `evidence.ts`, `matchups.ts`, `memberships.ts`, `calculationModels.ts`, `src/domain/calculation` 변경 없음이어야 한다. 기존 5개 고정 앵커 및 15 매치업 출력이 계속 회귀 통과해야 한다.
- 패키지 메타데이터 및 package-lock root version을 0.2.0으로 맞췄지만 의존성 버전과 모델 버전 Balanced1.2는 변경하지 않았다.
- 과거 버전의 독립적 byte-level snapshot은 `v0180LegacyCohort.ts`의 현재 데이터 필터만으로 충족되지 않는다. 이번 버전에서는 미래 평가 수정이 없으므로 구조 리팩터링을 하지 않았고, **차후 실제 점수 변경 직전 필수 검토 대상**으로 유지한다.
- **최종 CI/Pages:** 해당 PR final head의 성공한 Run ID 및 병합된 main/deployment SHA가 같은지 릴리즈 댓글에 별도 기록한다.
- **수동 브라우저 검증:** CI jsdom/Vitest는 실제 데스크톱·모바일 브라우저 화면 검증을 대신하지 않는다. 직접 확인하지 않은 상태는 완료라고 주장하지 않는다.
