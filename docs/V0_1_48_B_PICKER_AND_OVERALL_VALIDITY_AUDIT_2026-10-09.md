- 키보드 Up/Down/Enter, Escape 닫기, 대화창 Tab 포커스 순환, 닫기·결과 선택 후 **열기 버튼으로 포커스 복귀**, 바깥 배경 클릭 닫기, 현재/과거 소속 결과 및 그룹 선택 표시.
- Matchup 화면의 **독립적인 좌/우 59명 선택, 평가 시점, 동일 캐릭터 선택 제한, 랜덤/추천·교환 버튼**은 일절 변경하지 않음. 최근 선택·즐겨찾기·영구 저장은 아직 미도입.
- 기존 neutral UI 색 구성 및 내비게이션 패널 구조 유지. 실제 모바일 브라우저/기기 수동 UX 검증은 자동 jsdom 테스트와 별도다.

## 2. 질문 1 — 서로 다른 Core Stat 간 숫자 90/89 비교

**공격력 90이 방어력 89보다 전투력에서 우수하다는 결론은 나오지 않는다.**

- Attack은 목표 대상에게 가하는 타격력·실질 피해/돌파 능력, Defense는 회피·차단·피해 감소·상태 조건부 방어를 표현하는 **서로 다른 구성개념(construct)**이다.
- `PROJECT_SPEC.md §4.1`: `Attack > Defense` 단일 조건으로 승패를 산출하지 않는다. 비슷한 수치로 표시하더라도 '공격 1점'과 '방어 1점'이 서로 교환 가능한 동일 물리 단위라는 실증은 없다.
- **동일 축 안에서** A 공격 90 vs B 공격 89는 *현재 프로젝트 평가자·근거가 설정한 순서*라는 의미가 있지만, 여기서도 1점의 절대 정확도·상대 승률을 뜻하지 않는다.

## 3. 질문 2·3 — 전체 Overall 공식 검증

현행 코드:
- `src/domain/evaluation/score.ts`: `FinalStat = min(100, BaseStat + HakiRaw×0.5)`; 등급 E1/E2/E3은 계산에 **포함되지 않는다**.
- `src/domain/calculation/calculateCombatPower.ts`: Balanced 1.2는 **7 Final Stat 동일 가중 산술평균**. Haki Raw ×0.5는 이미 각 Final Stat에 반영되며 Overall에 다시 한 번 가산되지 않는다.
- `getStatRanking('overall')`: 평균의 **전체 정밀도**로 정렬하고 동점일 때만 동일 순위. 근소 차이의 불확실성 구간을 고려하는 알고리즘은 없다.

\[
Overall = \frac{Attack + Defense + Stamina + Speed + Technique + CombatIQ + Versatility}{7}
\]

이 방식은 다음 전제를 **규범적으로 채택**한다(작중 실증된 공리가 아님).
1. 서로 다른 스탯이 동일한 수치척도상에서 합산 가능
2. 모든 축이 Overall에 같은 한계 기여(1점당 1/7)
3. 특정 조건에서의 능력 간 상성·복합 효과·특화 역할의 중요도는 평균에 자동으로 반영되지 않음
4. 별도의 관찰 근거 부족, 평가 간 편차, 상대적 불확실성·판단 충돌을 Overall 숫자에 직접 표시하지 않음

### 실제 59명 데이터에서 관찰된 취약성

- 각 캐릭터 대표 Evaluation 59명 × 7축 = **413개**. 이 중 readiness `E1=29`, `E2=131`, `E3=61`, **미기재=192** (약 46.5%). `E1/E2/E3`은 수치와 독립적이고, 미기재는 근거가 없다는 뜻과 같지 않다. 그렇지만 **413축 전부에 충분도 정보가 일관되게 부여돼 있지 않음**은 사실이다.
- 전체 내림차순 58개 인접 점수 차이 중 **43개가 0.5점 미만**, **32개가 1/7점 이하(반올림 4자리 기준)**, **9개가 정확히 동점**. 이 수치는 현재 프로젝트의 점수들이 같은 부근에 밀집한다는 진단이지 평가자의 오차분산을 측정한 게 아니다.
- 한 캐릭터의 한 축을 **1점** 조정하면 Overall은 **약 0.143점** 이동한다. 2점은 0.286, 3점은 0.429. 따라서 소수점 셋째 자리의 Overall 차이나 1~2칸의 순위 차이는 평가자가 한 축을 1~3점 조정하는 것만으로 바뀔 수 있다.
- 실제 예: 키드 **84.571** vs 카타쿠리 **84.286**, 차이 **0.286점**. 한 축을 3점 변경하면 둘의 순서를 뒤집을 수 있다. **키드가 카타쿠리를 전투에서 이길 확률이 높다는 결론은 나오지 않는다.**
- 이것은 곧 Overall이 무의미하거나 모든 평가가 틀렸다는 뜻은 아니다. **현재 방식의 역할은 7축의 동일 가중 요약 지표**이며 신뢰도·상성·실전 승률까지 포함한 단일 '객관적 강함 수치'는 아니다.

## 4. 수치 신뢰도와 모델 타당도를 구분

| 평가할 성질 | 현재 보장하는가? | 해석 |
|---|---|---|
| 계산 재현성 | **예** | 동일한 Evaluation/Base/Raw/모델로 동일 Overall 계산 가능 |
| 코드/데이터 무결성 | CI가 검사 | 7축, Raw 중복/버전, UI 파생 데이터 관계 등 기술 검사 |
| 축 간 교환 가능한 1점 | **아니오** | 공격 1점과 방어 1점이 같은 실전 가치라는 경험적 근거 없음 |
| 채점자 간 합치(ICC 등) | **미검증** | 독립 채점자·반복 평가 결과가 없으므로 신뢰도 계수 주장 불가 |
| 점수의 수렴타당도/예측타당도 | **미검증** | 전투 시점·조건·상성 통제한 교전 표본으로 분석 필요 |
| Overall 승률/확률 | **아니오** | 독립적인 교전 모델/상성 비교/Evidence를 요구 |
| E1/E2/E3의 자동 신뢰도 반영 | **아니오** | 충분도는 점수 자체와 분리. 일부는 미기재 |
| 능력 사용 조건/상호배타적 상태 | **평균 자체에는 없음** | 킹 불꽃 ON/OFF, 스론 월광, 로·키드 팀전은 Evidence/매치업에서 보완 |

**특기:** 서로 다른 일곱 구성개념이어서 Cronbach alpha 같은 내적 일치도만으로 '종합 전투력 신뢰도'를 판단하는 것은 부적절할 수 있다. 여러 평가자 간 같은 축에 대한 일관성(예: ICC)과 조건을 통제한 사례 검증이 더 직접적이다.

## 5. 안전한 개선 순서 — 이번에 점수/계산 모델을 바꾸지 않은 이유

### 1순위 (제안): 'Overall = 균형 요약'임을 UI에 명시 + 능력 분포 우선 표시

- 현행 Overall/Balanced 1.2 계산은 그대로 유지; **'7축 균등 평균, 승률/확정 서열 아님'**을 결과 근처에 짧게 설명한다.
- 랭킹의 근소한 차이(예: 0.1~0.5)는 **해석 주의 메모**를 제공하되 새 등급/의미 없는 '신뢰도 90%'를 생성하지 않는다.
- 기존 7축 레이더·항목별 고유 능력·Evidence readiness를 Overall과 함께 주된 해석 기준으로 사용한다.
- UI 정보 우선순위 변경은 사용자 UX 결정 대상이므로 본 패치에서는 **제안만 기록**.

### 2순위: 근거 밀도와 평가자 민감도 감사

- 각 축에 E1/E2/E3 **누락 여부**를 확인하고, *등급을 채워 넣는 작업 자체가 근거 확보와 동일하지는 않음*을 명시.
- 근소한 Overall 순위의 **±1~3점 축별 민감도 분석**을 별도 참고 자료로 제공. 이는 실험적 오차막대가 아니고 순위 안정성 시나리오다.
- 적어도 고위 비교군에 대해 독립 평가자 2명 이상 같은 근거를 보고 각 축을 먼저 채점한 뒤 **ICC/채점 불일치 원인**을 검토.

### 3순위 (별도 기획 승인 필요): 다중 관점 요약·상성/조건 기반 매치업

- Balanced 기본 평균 유지 vs Attack-heavy / Defense-heavy / control-oriented 등 **시나리오별 가중 프로필**은 구체적인 전투 목적·상성 근거가 있을 때만 마련.
- 기존 상대별 Matchup Evidence가 있으면 **전투 당시 조건/방어능력-공격수단 궁합/환경/지속/동료**를 별도 평가. 자동 Overall 순위로 승패 단정하지 않음.
- 가중치 임의 조정/Overall 교체/E3 일괄 감점은 기존 59인 점수·랭킹과 Matchup 해석에 영향이 큰 모델 변경이므로 **PROJECT_SPEC 검토/사용자 명시 승인 전 금지**.

## 6. 코드 변경의 국소 테스트 범위

- 드롭다운 그룹 선택, 기존 그룹 칩 선택, 기존 헤더 검색 유지
- 전체 59명 목록/73 Membership 중복 제거, 검색·그룹 필터, 이명 검색, 전/현 소속 안내
- 검색 결과 선택의 그룹/인물 state 동기화, Escape/닫기/포커스 복귀, 모바일 Dialog CSS, Matchup 전용 2-player select 불변
- Core Stat, Raw Haki244, Evaluation62/434, Membership73, 기존 직접 Matchup15, Balanced 모델 불변
- 실제 브라우저/안드로이드 모바일 수동 스크롤·포커스·가독성 검증은 **별도로 해야 하며 CI jsdom 통과와 구분**.

**결론:** 프로젝트의 값은 재현 가능한 **정성 판단의 정량 요약**으로서 의미 있다. 다만 순위·점수의 소수점 정밀도가 그만큼 검증된 측정 정확도를 뜻하지 않는다. 사용자가 주장한 **개별 스탯 분포와 Evidence가 Overall보다 중요한 경우**는 많고, 특히 유사 Overall의 능력 특화 캐릭터 비교에서 그 효과가 크다. 새 측정 모델은 원칙·민감도·검증 계획이 수립될 때 별도 결정해야 한다.
